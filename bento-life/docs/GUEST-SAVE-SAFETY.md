# 로그인 선택과 저장 상태 안내

2026-11-11. 로그인은 선택 사항이며 게스트로 끝까지 플레이할 수 있다. 이 문서는 로그인 안전 UX의 첫 구현 범위다. Apple/Google 공급자 연결이나 출시 완료를 뜻하지 않는다.

## 실제 동작

- 새 판을 시작할 때만 로컬 저장 위험을 먼저 설명한다. 앱 삭제·기기 분실·브라우저 데이터 삭제로 기기 기록이 지워지면 계정에서 복원할 수 없음을 알리고, 기존 ‘계정과 저장’ 또는 ‘로그인 없이 계속’을 직접 고른다. 경고나 계정 화면을 여는 것만으로 새 판을 만들거나 기존 판을 덮지 않는다. 기존 이어하기에는 로그인·경고를 강제하지 않는다.
- 제목·게임·등굣길 위의 저장 상태 버튼으로 언제든 계정 화면을 연다. 등굣길에서 사용자가 직접 누르면 게임을 일시정지하고 닫은 뒤에도 명시적 재개를 기다린다. 저장 상태 변화가 자동 팝업이나 미니게임 중단을 만들지는 않는다.
- 첫 해 결산에만 계정 보관 안내를 넣는다. 다음 해 버튼은 그대로 쓸 수 있으며 ‘지금은 계속하기’나 계정 안내를 고른 사실을 기존 `prefs.seenTips` 안에 저장해 다시 열어도 반복하지 않는다. 새로운 저장 스키마·개인정보·익명 서버 계정은 추가하지 않는다.
- 로그인 뒤 직접 보관할 진행을 선택하고 업로드 완료를 확인해야 다른 기기에서 복원할 수 있다고 설명한다. 기존 guest 원본, 계정별 namespace, 충돌 선택 및 재시도 저널을 유지한다. 게스트와 계정의 하트·도감을 자동 합치지 않는다.

## 저장 완료의 근거

`save-status.ts`는 기기 저장 실패/읽기 차단을 최우선으로 표시하고, 기기 비동기 쓰기가 남았으면 저장 중으로 표시한다. 로그인 여부만으로 계정 보관 완료를 표시하지 않는다. `AccountSync`의 실제 상태·dirty/flight·서버가 확인한 snapshot과 결과를 사용한다.

- guest: 이 기기에만 저장, 계정 보관 안 됨.
- 로그인했지만 처음 보관할 기록을 아직 선택하지 않음: 진행 선택 필요.
- 기기에 저장했으나 변경 또는 전송 응답이 남음: 계정 저장 중.
- 전송 실패·오프라인: 계정 전송 대기. 로컬 기록과 저널을 남기며 기존 오프라인 플레이를 중단하지 않는다.
- 최신 변경의 서버 ACK를 확인하고 미전송 항목이 없음: 계정에 저장됨.
- 이전 확인본은 있지만 현재 재조회가 실패하거나 오프라인: 마지막 확인 시 계정에 저장됨, 연결 확인 필요.
- 충돌·형식/기기 저장 오류: 선택/확인이 필요하며 저장 완료라고 표시하지 않는다. 계정 화면에는 상세 원인과 기존 복구 동선도 남긴다.

동기화의 `ready`는 플레이 가능한 상태이며 서버 보관 완료와 다르다. 첫 선택이 로컬에 설치된 뒤 원격 전송이 실패할 수 있으므로 `ready`나 로그인 성공을 ACK로 취급하지 않는다. 앱 삭제·기기 분실 전 서버에 전달하지 못한 변경은 이 안내만으로 복구할 수 없다.

## 검증

- 기존 `npm ci` → **266개 테스트/15개 파일**(자동 플레이 2,000판 포함) → TypeScript/Vite 빌드를 통과했다. 응답 유실 뒤 pending 유지·멱등 재시도 ACK, 더 최신 미전송 변경, 기기 쓰기/오류 우선 표시를 검사한다. Native 인증 손상 UI 시험의 window 이벤트 mock만 새 구독에 맞게 보완했다.
- 폐기 가능한 브라우저 저장으로 실제 UI **21개 검사**: 320px 경고 문구/가로 넘침 없음, 기존 이메일 화면 이동·닫기, 게스트 시작, 기존 판 교체 동의 전 보존·이어하기, 첫 결산 inline 안내·다음 해 허용·닫힘 재실행 유지, 실제 저장 모듈의 지연/실패 알림을 확인했다. 저장 포트의 지연/오류는 시험용 어댑터다.
- 실제 앱/SDK/동기화 코드와 로컬에서 가로챈 합성 Auth/RPC로 **7개 검사**: 로그인과 저장 완료 구분, 업로드 실패 중 플레이 허용, guest 원본 보존, ACK 후 저장 완료, 재조회 실패 때 이전 확인본 표시를 확인했다. 실제 외부 계정·운영 API·제공자 OAuth 검증이 아니다.
- 실제 게임 엔진으로 만든 등굣길 fixture에서 **5개 검사**: 320/390px 저장바와 HUD 비겹침·가로 넘침 없음·결산 안내 미노출, 직접 계정 열기/닫기 때 일시정지 유지, 모든 실제 CSS의 상단 safe-area 값을 59px로 치환해 상단 바만 inset을 사용하고 HUD까지 추가 공백이 없음을 확인했다. 실제 iPhone safe area 검증과 구분한다.
- 독립 Claude 검토에서 발견한 확인창 history 중복과 safe-area 중복 여백을 수정했다. 실제 브라우저 **12개 검사**로 제목의 뒤로가기 및 엔딩→새 판 2회 반복의 history 길이 유지, 취소 후 엔딩 유지, 뒤로 한 번에 제목 복귀를 확인했다. 실제 Android 기기 버튼 검증은 별도다. 저장 중 문구는 반복 자동 저장을 과도하게 경고하지 않도록 짧게 표시한다.
- 첫 UI 시험의 결산 fixture는 실행 중 페이지의 pagehide 체크포인트가 덮어써서 이전 화면을 열었다. fixture 주입 전에 해당 시험 문서의 게임 쓰기 gate를 멈춰 원인을 고쳤고 전체 UI 시험을 다시 통과했다. 제품에서 사용자 기록을 직접 주입하거나 이 gate를 임의로 초기화하지 않는다.

기존 미리보기와 Native 자산·설정·현재 인증 복귀 주소는 이 작업에서 변경하지 않았다. 실제 공급자 설정, Native/실기기 OAuth, 동일 UID 연결, 소셜 삭제 재인증·공급자 grant 해제는 후속 범위다. UI/합성 응답 성공으로 소셜 로그인이나 기기 교체 복원 완료를 선언하지 않는다.
