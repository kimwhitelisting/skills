# Native 게스트 기록 확인과 가져오기

2026-11-11. 이메일 로그인과 같은 기존 계정 흐름에서 기기 기록을 찾는 경계를 보완했다. 소셜 로그인·출시 완료를 뜻하지 않는다.

## 저장소를 따로 읽는 이유

로그인 뒤 게임 저장소는 계정 UID namespace로 초기화된다. 이전 코드는 게스트를 WebView의 `localStorage`에서만 찾아, Preferences에만 남은 게스트 기록을 놓치거나 오래된 WebView 사본만 보여 줄 수 있었다. 저장소 초기화를 게스트→계정 순서로 두 번 실행하면 전역 저장 모듈의 상태가 섞이므로 그렇게 처리하지 않는다.

`guest-records.ts`는 접두사 없는 게스트의 통합 저장과 구형 run/dex/prefs만 읽는다. 인증 키·다른 계정·진행 중 계정 namespace를 읽거나 변경하지 않는다. 게임과 같은 로컬 검증 규칙으로 정상 여부를 판별하고 계정 업로드의 크기·추가 항목 제한은 별도로 표시한다. 따라서 기기에서 정상인 큰 기록을 손상으로 오인하거나 더 오래된 작은 기록으로 유도하지 않는다. 정상 통합 저장이 있으면 구형 조각보다 우선하며, 손상된 통합 저장을 구형 조각으로 조용히 대체하지 않는다. 각 출처를 기록 없음·정상·손상·읽기 불가로 구분한다. 잘못된 JSON이나 읽기 실패는 기록 없음이 아니다.

## 계정에 처음 저장할 때

- Native와 WebView에 각각 있는 기록의 이름·나이·하트를 보여 주고 사용자가 출처를 직접 선택한다. 서로 다른 정상본에는 비교 가능한 수정 시각·리비전이 없으므로 나이·하트만 보고 최신본을 자동 결정하지 않는다.
- 다른 출처가 손상/읽기 불가인 경우 그 상태와 더 최신 기록이 남아 있을 가능성을 알린다. 정상으로 읽은 출처만 명시적으로 가져올 수 있고, 다른 원본은 지우지 않는다.
- 선택 직전 두 출처를 다시 읽는다. 내용·읽기 상태가 바뀌거나 로그인 계정이 전환됐다면 이전 후보를 가져오지 않고 재확인한다.
- 선택한 진행은 기존 `AccountSync`의 설치 의도·UID별 저장·업로드 ACK 절차로 들어간다. 게스트 원본에는 쓰지 않으며 로그인 성공만으로 저장 완료라고 표시하지 않는다.
- 이미 계정 진행이 있으면 기존 계정 복원과 충돌 규칙을 유지한다. 게스트 원본을 알리지만 이를 계정 진행에 자동 병합하거나 덮어쓰는 새 경로는 열지 않는다. 기존 계정으로 다른 게스트 기록을 교체하는 기능은 별도 명시적 충돌·교체 흐름이 필요하다.

## 로그아웃 뒤 게스트로 돌아올 때

기존 Native 부팅은 정상 WebView 사본을 우선 사용하고 이후 Preferences에도 미러링했다. 두 사본이 다르면 대안 기록이 사라질 수 있어, 게스트 부팅 전에 읽기 전용 검사를 한다. 서로 다른 정상본, 정상본과 손상본의 조합, 읽지 못한 출처가 있으면 게임을 마운트하거나 저장소를 초기화하기 전에 확인 화면에서 멈춘다.

정상본을 직접 선택하면 두 출처에서 읽은 정확한 원본 바이트를 **각 원래 저장소의 내용 기반 recovery 키에 보관하고 다시 읽어 일치를 확인한 뒤** 선택본을 canonical 저장으로 적용한다. 보관 도중 다른 기록이 생겼는지도 다시 읽는다. 원본 보관·읽기 확인이 실패하면 canonical을 변경하지 않는다. 적용 중 한쪽 쓰기가 실패해도 양쪽 원본은 이미 보관돼 있고 재실행/재확인할 수 있다. 동일 원본의 재시도는 같은 보관 키를 재사용하고 실제 바이트가 다르면 충돌 suffix로 분리해 덮지 않는다. 읽기 확인은 저장 API에서 같은 값을 돌려줬다는 증거이며 OS 디스크 반영이나 강제 종료 내구성까지 보장하지 않는다. 실제 기기 강제 종료 시험은 별도다.

읽지 못한 원본은 안전하게 보관할 수 없으므로 선택·새 게임으로 우회하지 않는다. 읽기가 복구된 뒤 다시 확인한다. 기다리는 동안 ‘읽을 수 있는 게스트 원본 내보내기’로 확인 가능한 사본을 보관할 수 있다. 정상본이 하나뿐이거나 키 순서가 달라도 구조적으로 같은 내용이면 기존 단일 scope 초기화를 사용한다. 양쪽 모두 손상되어 정상 후보가 없는 경우는 기존 손상 저장 복구 흐름에 맡긴다. 계정 namespace와 인증 토큰은 이 게스트 선택 절차에서 변경하지 않는다.

## 읽기 전용 복구 내보내기

현재 게스트 통합본·구형 run/dex/prefs·각 last-good과 정해진 게스트 recovery 키만 내보낸다. Native에만 남은 보관본도 포함하며 `native:`·`unsaved:` 접두사의 기존 게스트 보관본을 지원한다. 손상된 통합본이 있어도 다른 읽을 수 있는 구형 원본을 빠뜨리지 않는다. 인증 키·계정 UID namespace·클라우드 전송 저널은 읽지 않는다. 읽지 못한 출처·키와 목록 조회 실패를 파일에 기록하며 일부만 담은 경우 화면에도 알린다. 이 파일은 민감할 수 있는 게임 기록의 수동 보관본이며 새 자동 복원 기능은 아니다.

Native 공유 transport는 계정 부팅 전에 등록한다. 초기 보호 화면에서 게임 마운트가 중단돼도 사용자가 직접 내보낼 수 있다. 취소·실패는 완료로 표시하지 않으며 공유 창 반환도 수신 앱에 파일이 실제 보관됐다는 증명으로 취급하지 않는다. 내보내기는 canonical/보관 원본을 변경하지 않는다.

## 검증 범위

Native Preferences와 같은 비동기 저장 포트를 사용한 계약 시험과 실제 `bootAccount`/`AccountSync`/게임 저장 모듈을 연결한 시험을 추가했다. Native에만 남은 최신 게스트, 구형 조각, 다른 WebView 사본, 손상·읽기 실패, 선택 후 변경, 읽기 중 계정 전환, 보관 확인 실패, 보관 중 변경, 중단된 적용의 재시도, 기존 계정 자동 복원, 로그아웃과 다음 부팅을 **새 검사 23개**로 확인했다. 인증 응답·RPC·DOM은 격리된 시험용 객체이며 실제 제공자 계정이나 운영 서버를 사용하지 않는다.

기존 `npm ci` → **전체 289개 테스트/16개 파일** → TypeScript/Vite 빌드를 통과했다. 폐기 가능한 브라우저·Native adapter/공유 transport fixture의 실제 계정 UI 12개 검사로 부분 내보내기·취소·실패·출처 선택·보관 실패 후 원본 유지·명시 선택 후 재실행을 확인했다. 첫 시험 fixture의 UTF-8 선언 누락을 고친 뒤 같은 검사를 통과했다. 실제 iPhone/Android 기기, Keychain, 설치형 앱 갱신, 실제 계정의 복원 검증과 구분한다. 구현 검증과 별도로 아래 후속 패키징·미리보기 반영을 진행했다.
