# Play 스토어 등록 초안

> 공개 GitHub 기능 브랜치의 출시 전 초안이다. 스토어에 제출하거나 시행 중인 공식 개인정보처리방침으로 게시한 상태는 아니다. 개발자 이름·연락처·개인정보처리방침 시행일은 운영자 응답 대기다. 최종 앱·SDK·실기기 결과를 확인하기 전에는 출시 완료로 취급하지 않는다. 검증 기준: 2026-11-06, 코드 `8fd57de` 이후 Native 내보내기 변경 후보.

## 이름 (최대 30자)
**냠냠졸졸: 도시락 들고 몰래 육아** (스토어 제목, 18자)
- 앱 이름(아이콘 밑): **냠냠졸졸**
- 이름 뜻: 먹이고(냠냠) 따라가는(졸졸) 게임. 앱 이름엔 도시락이 없으니 "도시락"·"육아" 검색어는 부제가 맡는다
- 영어 표기: Nyamnyam Joljol

## 짧은 설명 (최대 80자)
도시락 싸들고 졸졸 따라다니면, 아이를 얼마나 잘 키울 수 있을까? 1살부터 스무 살까지 도트 육아 시뮬레이션.

## 자세한 설명 (최대 4000자)
```
도시락 싸들고 졸졸 따라다니면, 아이를 얼마나 잘 키울 수 있을까?

매일 아침, 아이가 오늘 사정을 말해요.
"오늘 체육 있어!" "시험이야…" "…아무거나."
주식·메인·반찬 세 칸을 채워 도시락을 싸 주세요. 아이의 취향은 먹여 봐야 알아요.

그리고 선택의 순간.
믿고 보낼까요, 몰래 따라가 볼까요?
나무 뒤, 전봇대 뒤에 숨어 등굣길을 따라가요. 아이가 뒤돌아보면 얼음!
가까이 있을수록 ♥가 쌓이지만, 들키면… 사춘기 아이는 오래 기억해요.
위기의 순간, 달려갈지 참을지도 당신의 몫이에요.

■ 1살부터 스무 살까지
아기 이유식부터 야자 도시락, 마지막 도시락까지. 아이는 8단계로 자라고, 키는 해마다 기린 키재기에 새겨져요.

■ 52가지 엔딩
명의, 국가대표, 고양이 의사… 그리고 "평생 도시락 받는 어른", "부모 도시락을 디스하는 인디 밴드", "사진집 「뒤에서 본 부모」".
항상 해피엔딩일 수는 없어요. 스무 살이 되기 전에 끝나는 이야기도 있어요.

■ 90가지가 넘는 이벤트
돌잡이, 유치원 첫 등원, 방문이 닫힌 날, 형광 분홍 머리, 첫사랑, 수능 날 아침…
하트 상점에서 강아지·피아노·필름 카메라 같은 이야기 꾸러미를 열면 새 이야기가 시작돼요.

■ 해마다 한 장, 사진첩
그해의 한 장면이 폴라로이드로 남아요. 스무 장을 다 모으면 한 아이의 앨범이 완성돼요.

■ 600가지 도시락 메뉴 도감
재료 조합마다 이름이 있는 메뉴, 숨은 특별 메뉴까지.

과잉보호와 방임 사이, 정답 없는 육아를 도시락 하나로 웃으며 겪어 보세요.
```

## 앱 콘텐츠 설문 — 답변 초안
| 항목 | 초안 | 메모 |
|---|---|---|
| 타깃 연령 | **18세 이상** (부모 · 성인) | 아동이 포함되면 가족 정책·광고 제한. 그림체가 귀여워도 대상은 부모 |
| 광고 포함 | 현재 앱은 **아니요** | 광고·분석 SDK 없음. 향후 도입 여부와 신고는 별도 작업 |
| 콘텐츠 등급 (IARC) | 폭력: 가벼운 부상 묘사(교통사고로 다침, 피 없음) · 담배 언급(교복에서 담배 냄새) · 연애(손 잡기 수준) · 가상 결제/도박: 없음(코인·현질은 이야기 속 사건) · 사용자 간 소통: 없음 | 12세 이용가 정도로 예상 |
| 데이터 보안 | 현재 앱 코드에는 개발자 서버 전송·광고·분석 SDK가 없음. **최종 양식 답변 미확정** | OS 백업·기기 이전과 사용자가 내려받는 복구 JSON을 구분한다. “모든 저장은 기기 안”이라고 단정하지 않는다. 최종 배포물과 제출 시점 공식 양식 정의에 따라 재확인 |
| 개인정보처리방침 URL | **공식 방침 URL 미정·공식 게시 보류** — [공개 저장소의 출시 전 초안](privacy-policy.md) | 운영자·문의 이메일·시행일 확정 및 최종 검토 후 공개 URL 준비 |
| 정부 앱 · 뉴스 앱 · 금융 기능 | 아니요 | |

## 출시 전 확인
- [x] 패키지 이름 확정 — `com.paranstudio.dosirak`
- [ ] [계정 저장과 결제 요구사항](STORAGE.md#계정-저장과-결제-요구사항): 로그인한 계정에 진행 저장·복원을 구현·검증한다. 결제 도입을 선택하면 구매 검증/계정 귀속/중복 지급 방지·환불·철회 기준도 적용한다. 현재는 로그인·서버 저장·IAP가 없으며 무료 내부 테스트에 IAP는 필요하지 않다.
- [ ] 결제 유형(광고 제거 / 아이템·하트 / 구독), 로그인·백엔드, 게스트 및 기존 로컬 기록 이전 정책을 Owner와 확정한다. Owner 답변은 “아직 미정 — 설계부터 보고 결정”이다. [설계안과 결정표](ACCOUNT-DESIGN.md)를 검토하며 유료 하트나 특정 공급자를 선택한 것으로 취급하지 않는다.
- [ ] 재설치·기기 변경·계정 전환·동기화 충돌·네트워크 단절의 실제 결과를 확인한다. 결제를 도입하면 대기/환불·중복 거래/구매 복원도 확인한다. 기존 하트·owned·백업 파일을 유료 권리로 신뢰하지 않고, 계정/결제 도입 후 개인정보처리방침과 스토어 신고를 실제 구현에 맞춘다.
- [ ] 운영자 이름·문의 이메일·시행일 확정 및 개인정보처리방침 최종 검토·공개 웹 주소 준비 — [privacy-policy.md](privacy-policy.md)의 빈칸을 임의로 채우지 않는다.
- [ ] 출시용 업로드 키 보관·서명한 AAB 검증 및 Play 제출 설정. debug APK 빌드/서명 성공은 출시 서명 완료가 아니다.
- [ ] Android 실기기에서 설치→한 판→종료/재실행, 저장·복귀·뒤로가기·소리·진동·오프라인 및 복구 JSON 공유/취소/파일 확인. 웹 UI·합성 저장 오류 테스트와 구분한다.
- [ ] Android OS 백업·기기 이전·재설치 복원 및 삭제 결과 확인. 현재 `allowBackup=true`; 정확한 검증 근거와 공식 URL은 [개인정보처리방침의 검증 메모](privacy-policy.md#출시-전-검증-메모-정책-본문과-함께-확정-필요).
- [ ] iOS도 출시할 경우 Xcode 초기 설정·compile·배포 계정/서명·TestFlight 및 실제 iPhone 저장/복귀·OS 백업/삭제 확인. [MAC-BUILD.md](MAC-BUILD.md), [PLAYTEST.md](PLAYTEST.md)의 미검증 범위를 따른다.
- [ ] 최종 배포물 기준 데이터 보안·대상 연령·콘텐츠 등급 신고 재확인. 새 게임은 도감/하트를 유지하며, 복구 원본과 내보낸 파일은 전체 삭제되지 않음을 고지한다. 저장 범위는 [STORAGE.md](STORAGE.md).
