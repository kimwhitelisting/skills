## 한 줄
**「냠냠졸졸」** (스토어 제목 「냠냠졸졸: 도시락 들고 몰래 육아」) — **"도시락 싸들고 쫓아다니면 애를 얼마나 잘 키울 수 있을까?"** 0살부터 스무 살까지 매년 아침 도시락을 싸고, 배웅하거나 몰래 따라가며 아이를 키우는 모바일 세로 도트 인생 시뮬레이터. 안드로이드 먼저 출시 예정 (개발자 등록 완료), 기존 수익화 계획은 광고 + 광고 제거였으나 미구현이며, 현재 결제 유형은 설계안을 본 뒤 결정하기로 했다.

## Native 게스트 원본 보존 (2026-11-11)

로그인한 계정과 별도로 Native Preferences/WebView의 게스트 기록을 읽고, 정상·없음·손상·읽기 불가를 구분한다. 첫 계정 저장에서는 출처를 직접 고르며 가져오기 직전 다시 확인한다. 로그아웃 뒤 두 게스트 사본이 다르면 자동으로 덮지 않고, 양쪽 원본을 보관·읽기 확인한 뒤 명시 선택본으로 이어간다. 반복 보관은 내용별로 재사용하고, 읽기 장애 중에도 읽을 수 있는 게스트 원본·기존 보관본을 부분 상태와 함께 내보낼 수 있다. [경계·검증·남은 제약](NATIVE-GUEST-PRESERVATION.md)을 따른다. 기존 계정에 다른 게스트를 덮어쓰는 기능·실제 소셜 로그인·Native 설치 갱신은 포함하지 않는다.

## 로그인 없이 시작하기 · 저장 안내 (2026-11-11)

Owner 선택대로 로그인은 선택 사항이다. 새 판을 시작하기 전에 앱 삭제·기기 분실·브라우저 데이터 삭제 위험과 ‘로그인 없이 계속’을 안내하고, 기존 진행의 이어하기는 막지 않는다. 게임·등굣길에도 저장 상태를 표시하며, 기기 쓰기/오류·전송 대기·서버 확인 완료를 구분한다. 첫 한 해 결산에서 계정 보관을 한 번 권하고 닫힘 선택을 저장한다. [구현·검증 범위](GUEST-SAVE-SAFETY.md)를 따른다.

이 변경은 실제 Apple/Google 로그인·연결을 구현한 것이 아니다. 기존 이메일 계정은 유지하고 가짜 공급자 버튼을 노출하지 않는다. 소셜 로그인은 Native/web 복귀, 기존 이메일 계정 연결, 비밀번호 없는 계정의 안전한 삭제·공급자 권한 해제까지 별도 구현·실검증해야 한다. 이번 소스 검증은 기존 미리보기·Native 설치 앱을 자동 갱신하지 않는다.

### 개발 미리보기 반영 (2026-11-11)

`fd6acc5` 소스에서 기존 공개 클라이언트 설정을 유지해 `build:preview`를 완료하고, 이전 파일을 별도 보관한 뒤 개인 접속용 미리보기를 교체했다. Mac에서 로컬 HTTP와 Tailscale HTTPS가 같은 새 번들을 반환함을 SHA-256으로 확인했다. 새 게스트 안내·저장 상태를 미리보기에서 확인할 준비가 됐으며, 이번 갱신 후 아이폰에서 직접 조작한 검증은 아직 없다. Native 자산·설치 앱은 변경하지 않았다.

## 인증 메일 연결 — Auth 흐름 확인 남음 (2026-11-11)

냠냠졸졸 전용 Supabase에 Resend custom SMTP와 한국어 가입 확인·비밀번호 재설정 [템플릿](AUTH-MAIL.md)을 적용하고 저장 후 전체 원문 일치를 확인했다. 발송 도메인 검증과 일반 시험 메일 한 통의 제공자 **Delivered**를 확인했지만 실제 수신함 확인·Supabase Auth 링크의 가입/복구 전체 흐름은 아직 남아 있다. 루트 도메인의 지원 수신·사이트와 기존 개발 복귀 주소는 유지했다.

후속 소스에서 “초대된 테스트 이메일만” 안내를 스팸함 확인·재요청 안내로 고쳤다. [계정 웹](ACCOUNT-WEB.md)에 가입 확인 전용 결과와 임시 세션 폐기를 추가하고, 격리 Auth/Mailpit의 실제 가입·복구·명시적 삭제 및 263개 테스트를 검증했다. 공개 호스팅·Auth 복귀 등록·실제 발송 후 복귀는 다음 단계다. 기존 미리보기·Native 패키지·개발 callback은 갱신하지 않았으며 개인 계정 복원을 대신 검증하지 않았다.

## 최신 개발용 기기 빌드 — 설치 대기 (2026-11-10)

소스 `749008f`로 재현 설치, **257개 테스트**, 웹 빌드와 Android/iOS sync를 통과하고 Android Debug APK와 개발 서명된 iPhone Debug `.app`을 새로 만들었다. 두 패키지의 현재 웹 파일 **14개**가 빌드 출력과 일치하며 Android v2 서명과 iOS deep/strict 서명 검사를 통과했다. 이전 iPhone 빌드와 서명 식별자·팀·Keychain 그룹 목록·계정 서버 호스트가 같은 것도 비교했다. 프로비저닝 만료는 **2026-11-14 08:33 KST**다. 상세 범위는 [Mac 빌드 기록](MAC-BUILD.md#2026-11-10-최신-개발용-기기-빌드)을 따른다.

**새 빌드는 아직 iPhone에 설치하지 않았다.** 연결된 기기 조회가 connection reset/timeout으로 실패해 설치·실행이 대기 중이다. 기존 앱과 기록을 삭제하지 않았으며, Owner가 미룬 설치형 앱의 개인 계정 복원 확인은 계속 미확인으로 남긴다. 빌드 당시 SMTP와 기존 Tailscale 인증 복귀 주소를 변경하지 않은 **개발용 후보**이며 출시 후보·TestFlight 빌드가 아니다.

## 앱 밖 계정 삭제 후보 (2026-11-10)

게임 저장소와 분리한 [웹 계정 삭제·비밀번호 복구](ACCOUNT-WEB.md) 후보를 추가했다. 지원 수신 주소는 확인됐고 SMTP 연결은 위 후속 기록을 따른다. 이 웹 후보의 공개 주소·운영 배포와 실제 메일 복귀 검증은 미완료다. 기존 앱 안 삭제와 웹 삭제의 기기 캐시 처리 범위를 구분하며, 웹은 서버의 명시적 성공만 완료로 표시한다.

## 테스트 도구 유지보수 (2026-11-10)

Vitest 4.1.12 exact와 기존 npm의 재현 설치로 240개 테스트를 통과했다. 현재 audit 전체/production은 0이며 runtime 의존성과 일반·미리보기 출력은 유지됐다. [업데이트 근거·검증 범위](MAC-BUILD.md#2026-11-10-테스트-도구-보안-업데이트)를 따른다. 테스트 코드나 앱 동작은 변경하지 않았다.

의존성을 추가·업데이트할 때 npm 10의 `install`에서 `edgesOut` 오류가 재현되면, MAC-BUILD의 격리 resolver로 lockfile을 계산한 뒤 기존 `npm ci`로 재현 검증하는 절차를 따른다.

## 실행
```bash
cd bento-life
npm ci
npm run dev            # http://localhost:5173
npm test               # 게임 규칙 + 저장/복귀 회귀 + 자동 플레이 2,000판
npm run endings        # 플레이 성향별 엔딩 분포 (약 6천 판)
npm run balance        # 성향별 평균 스탯
npm run build:preview  # dist-preview/*.single.html (본 게임 + 맛보기들)
npx tsc --noEmit -p .  # 타입 검사
```
- 미리보기 서버는 현재 작업이 시작한 프로세스/PID 또는 등록된 해당 서비스만 종료한다. 포트 번호만으로 종료하면 다른 프로젝트 서버를 끌 수 있다.
- 스크립트 실행은 `vite-node` (node strip-types는 일부 문법을 못 읽음)

Capacitor로 감쌌다 (`capacitor.config.ts`, 패키지 이름 **`com.paranstudio.dosirak`** 확정, android 폴더는 깃에 올라가 있다). 휴대폰 글자 크기 설정은 무시한다(웹뷰 글자 배율 100% 고정, `scripts/android-assets.ts`가 MainActivity에 넣는다). 빌드·서명·Play 등록은 [`ANDROID.md`](ANDROID.md), 스토어 문구·설문 초안은 [`STORE.md`](STORE.md), 개인정보처리방침 초안은 [`privacy-policy.md`](privacy-policy.md). 스토어 그래픽은 `npm run store:art`, 스크린샷은 `npm run store:shots` → `art-src/store/`.

## 글 점검
`npm run text:dump` → `art-src/text-dump.md`에 이벤트·엔딩·아침 요청의 모든 문장이 (받침 있는 이름/없는 이름, 스탯 높음/낮음 갈래까지) 한 파일로 모인다. 문장을 고친 뒤 다시 뽑아서 읽는다.
- 부모 성별은 정하지 않는다: 서술은 "부모님", 선생님 말은 "부모님"/"걱정 마세요" 식으로. "어머님/아버님" 같은 빗금은 쓰지 않는다 (아이 말투의 "엄마아빠"는 괜찮다)
- 아이 성별에 따라 달라지는 말(형·누나 / 언니·오빠)은 `s.child.gender`로 갈라 쓴다
- 2살 어린이집 → 3~5살 유치원 → 6살~ 학교 (코드 나이)

## 규칙 (깨지면 테스트가 실패)
- 이벤트·엔딩을 추가하면 `src/pixel/event-scenes.ts`의 `SCENES` / `ENDING_SCENES`에 장면을 꼭 넣는다
- 재료를 추가하면 `npm run gen:menus` (모든 조합의 메뉴표 재생성)
- 0~19살 매년 나이 이벤트가 하나씩 있어야 한다
- 텍스트의 `{c}` = 아이 이름(민준이/서아), `{v}` = 부르는 말(민준아/서아야), `{kind}` = 아들/딸

## 밸런스 현황 (`npm run endings`)
- 40개 중 38개가 봇 플레이에서 나온다. 「잔병치레 어른」「대기업 과장님」은 일부러 못 해야(정크 위주, 행복 바닥) 나온다
- 매일 따라다니면 거의 100% 「평생 도시락 받는 어른」 (의도)
- 해피가 아직 가장 많다 — 더 씁쓸하게 조일지는 직접 플레이해 보고 정할 것
- 끝날 때 반찬값 평균 약 20 (12~25% 판에서 할머니 찬스)

실제 화면 재현 버그와 회귀 확인은 [PLAYTEST.md](PLAYTEST.md)를 따른다.
저장 형식 전환·복구·화면 체크포인트의 원본은 [STORAGE.md](STORAGE.md)다. 이전 코드로 되돌릴 때 snapshot 호환성을 먼저 확인한다.
로그인한 계정에 진행을 저장하고 결제를 제공하려는 요구는 [계정 저장과 결제 요구사항](STORAGE.md#계정-저장과-결제-요구사항)을 따른다. 이메일 로그인·계정 저장은 구현·웹 실기기 검증을 완료했고 IAP는 없다. 로컬 복구나 계정 진행 복원을 구매 복원 완료로 취급하지 않는다.
